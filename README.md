## 建模要点

### B1 恒温水箱

温度低于 20℃ 且水箱有水时闭合继电器加热；达到 100℃ 断开电源；**无水时绝不闭合继电器**（缺水保护）；水箱烧坏进入维修；23:00 断电休眠，07:00 恢复。

图中把「监测 / 加热 / 缺水告警 / 维修」四个状态收进**复合状态「运行中」**，「23:00 断电」「07:00 恢复」画在复合状态的外边界上——否则每个子状态都要单独连一条线到休眠，既重复又容易漏。代码同样在 `handle()` 入口统一处理这两个时间事件，图与代码严格对应。

### B2 控制面板

读取键入字符 → 凑满 4 位比对密码 → 正确进入功能选择，错误累计 3 次锁定 120 秒 → 超时自动解锁。

「验证密码」是**决策节点（choice）**而不是状态：它没有持续时间，是瞬时判断，画成状态会被问“这个状态停留多久”。锁定计时抽象成 `SimClock`，测试里 `advance(120000)` 直接跨过 120 秒，不必真等两分钟。

### B3 字符串提取

三个状态 `NORMAL` / `IN_STRING` / `ESCAPE`。关键在于**顺序**：在 `IN_STRING` 里必须先判断反斜杠、再判断双引号，否则 `\"` 中的引号会被误当成字符串结束符——这正是题目示例最容易出错的地方。

## 测试覆盖

`StateMachineTests` 共 39 条断言，重点覆盖边界：

- 恰好 20℃ 不加热、恰好 100℃ 断电；
- 无水时无论温度多低都不闭合继电器；补水后恢复加热；
- 锁定第 119 秒仍然拒绝按键，第 120 秒解锁；锁定期间按键被丢弃；
- `\"` 不被当作结束引号、`\\` 转义、空字符串、未闭合字符串被丢弃。
